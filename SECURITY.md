# Security Policy

Security is especially important for systems involving wallets, smart contracts, payments, licensing, and AI inference.

## Reporting a vulnerability

**Please do not disclose exploitable vulnerabilities in public issues or discussions.**

Send a private report to `SECURITY_EMAIL_OR_GITHUB_PRIVATE_REPORTING_URL` and include:

- A concise description and potential impact
- Affected repository, component, version, or commit
- Reproduction steps or a proof of concept that does not harm users or systems
- Any suggested mitigation, if available

Replace the placeholder above with a monitored security contact or enable GitHub Private Vulnerability Reporting before publishing.

## Please avoid

- Accessing, modifying, or deleting data that is not yours
- Disrupting production services or testing against real user funds
- Publishing secrets, personal data, or exploit details before coordinated disclosure

## Scope and response

Maintainers will acknowledge reports as soon as reasonably possible, investigate, and coordinate remediation and disclosure with the reporter. Do not assume a particular response time until an official service-level commitment is published.

This policy does not grant permission to perform testing outside systems you own or are explicitly authorized to test.
